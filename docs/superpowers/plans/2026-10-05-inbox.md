# Olympus Inbox

Goal: one quiet, installation-wide view of tasks that need human attention.

Architecture: read-only projection of existing task, exact-run interaction, runtime and recovery state. No new task statuses, notification queue, automatic retries or execution limits. Existing task pages retain all actions and their guards. React list/detail view with profile/project filters and a sidebar count.

Stack: Express, SQLite, React, existing Hermes history adapter.

Approved scope: Questions & approvals, Ready for review, Needs help; all active local profiles by default. One item per task. Exclude Bots, completed tasks, healthy runs and automatic recovery. Reading an item changes nothing. Preserve Project access and profile isolation. No Linear integration or deployment.

Implementation:
1. Add route regression tests for classification, resolution, current-run identity, profile lifecycle, Project access and preview races. Observe failure before implementation.
2. Implement read-only aggregation and lazy saved-reply previews. Revalidate attention identity and access after history reads; expose no raw worker errors.
3. Add Inbox context, page, filters, preview, cross-profile task links and sidebar count. Refresh on focus and periodically; clearly show failed refreshes. Keep Markdown artifact links scoped to the item profile.
4. Test browser behavior with disposable local fixtures, including mobile, filters, selection and task links. Run regression tests, full tests, typecheck, build and diff review.

Review focus: stale questions must never authorize action; preview reads must not mutate task/read state; recovery must not create false blockers; profile changes and access revocation must not return another task's history. Preserve existing uncommitted steering changes.
